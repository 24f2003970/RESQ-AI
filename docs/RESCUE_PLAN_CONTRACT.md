# Rescue plan contract

`POST /api/v1/scenarios/{scenario_id}/rescue-plans` computes and persists a proposal with scenario ID, simulation state version, reset epoch, infrastructure revision, tick, ranked destinations, routes, assignments, unreachable sites, solver status, baseline comparison, and objective. `GET /api/v1/rescue-plans/{plan_id}` retrieves it. `POST /api/v1/rescue-plans/{plan_id}/decision` accepts `{ "action": "approved" | "rejected", "expected_version": n, "reason": "..." }`. Saving, editing, approving, and rejecting serialize through SQLite `BEGIN IMMEDIATE` and require the current state version, epoch, and infrastructure revision to match the saved proposal. Stale proposals cannot be modified or approved and are marked superseded. A human approval reserves assigned units for the scenario epoch; proposals generated afterward exclude those units. Part 8 missions support explicit completion and commander return-to-service; release is never automatic. Reset starts a new epoch and makes that epoch's inventory available again.

`PATCH /api/v1/rescue-plans/{plan_id}/assignments` accepts an expected version and a list of `{unit_id,destination_id}` pairs. It checks saved route feasibility, capacity, unit availability, and uniqueness before recomputing comparison metrics.

Road closure and reopen endpoints update an infrastructure revision scoped to the scenario's current epoch. The closure update reads the current epoch and commits with `BEGIN IMMEDIATE`, so it serializes against reset and proposal persistence. A closure change invalidates pending proposals; save/modify/decision also re-check the revision as a transactional safeguard. A reset begins a new epoch with no inherited manual closures. Replay is read-only: it reconstructs physical state in the current epoch, while the current epoch's closure overlay and resource reservations remain authoritative; rescue-plan generation always uses the current persisted scenario snapshot rather than a replay snapshot.

Approval records commander intent only: Part 5 does not create or execute simulated rescue missions. The scenario database is authoritative for physical state; the epoch-scoped closure overlay is authoritative for commander planning constraints.
