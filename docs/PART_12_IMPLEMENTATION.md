# Part 12 — ML Reliability and Uncertainty

## Scope

Part 12 adds reproducible calibration, feature-support monitoring, failure/subgroup analysis, and simulation-grounded sensitivity experiments to the existing local synthetic flood classifier. It extends the existing Model Intelligence Lab, inference API, rescue-planning eligibility checks, agent trace evidence, and Judge Mode. The physical flood simulation remains the source of current water state; ML never authorizes a rescue action.

## Implemented behavior

- Reproduced the v1 dataset from 72 scenario seeds and preserved its grouped 42/15/15 train/validation/test membership and model artifact checksum.
- Fit a scenario-grouped out-of-fold Platt calibrator from development scenarios only. Nested grouped evaluation gates adoption.
- Evaluated raw and calibrated scores on the original untouched test groups; saved diagram bins, Brier score, log loss, fixed-bin ECE, ranking and threshold metrics.
- Added interpretable feature-wise support status (`within_observed_support`, `edge_of_observed_support`, `outside_observed_support`, or invalid/schema mismatch), with thresholds fit only on training and validation data.
- Added false-positive/false-negative examples and scenario-aware subgroup metrics. Small groups are counts-only.
- Added validation-only flood-engine perturbations for rainfall, river stage, and drainage.
- Added `/api/v1/ml/reliability` and `/api/v1/ml/sensitivity`; inference exposes calibration/support status and preserves a degraded fallback if reliability artifacts cannot be validated.
- Excluded unsupported future labels from rescue-plan eligibility and agent hazard forecast evidence. Existing physical simulation and commander approval contracts remain authoritative.
- Extended Model Intelligence Lab, building inspector, and read-only Judge Mode with reliability evidence and stale-response protection.

## Reproduction

From `backend/`, use the existing `.venv` and `flood_exposure.csv` generated with `app.ml.dataset`. The CSV is generated into a local temporary directory and is not committed.

```powershell
$audit = Join-Path $env:TEMP 'resq-ai-part12'
New-Item -ItemType Directory -Force -Path $audit | Out-Null
\.venv\Scripts\python.exe -m app.ml.generate_dataset --csv (Join-Path $audit 'flood_exposure.csv') --metadata (Join-Path $audit 'dataset_metadata.json')
\.venv\Scripts\python.exe -m app.ml.train --dataset (Join-Path $audit 'flood_exposure.csv') --dataset-metadata (Join-Path $audit 'dataset_metadata.json') --artifacts (Join-Path $audit 'artifacts')
Copy-Item (Join-Path $audit 'dataset_metadata.json') (Join-Path $audit 'artifacts\dataset_metadata.json') -Force
\.venv\Scripts\python.exe -m app.ml.reliability --dataset (Join-Path $audit 'flood_exposure.csv') --artifacts (Join-Path $audit 'artifacts')
\.venv\Scripts\python.exe -m app.ml.sensitivity --dataset-metadata (Join-Path $audit 'artifacts\dataset_metadata.json') --artifacts (Join-Path $audit 'artifacts')
```

The evaluation artifacts contain the exact configuration, split IDs, checksums, and measurements. Timings are local development-machine observations, not service guarantees.

## Limitations

All labels and evaluation examples are generated by the same synthetic simulator family. There is no real-world flood dataset, external validation, causal explanation, calibrated physical uncertainty model, or safety certification. Feature support is a warning about observed synthetic feature ranges; it cannot guarantee correctness or detect every unsafe condition. No Part 13 work is included.
