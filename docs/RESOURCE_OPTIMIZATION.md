# Resource optimization

The available compatible ground units and accessible destination routes feed a deterministic exhaustive assignment search. Each unit and each destination can appear at most once; only standby ambulances and ground rescue teams participate. Boat missions are explicitly unsupported. Unit capacity caps the number of occupants targeted in a single mission. The objective maximizes the sum of capacity-covered priority (`priority × min(unit capacity / destination occupants, 1)`) less 0.15 points per synthetic route minute. The implementation enumerates assignments and reports `optimal_exact_enumeration`; it is exact for the enumerated objective, not for real-world outcomes. A commander may edit assignments to any route/capacity-feasible unit-destination pair saved with the proposal; edited assignments are validated and comparison metrics recomputed.

The baseline uses the same unit inventory, accessible routes, and exclusive constraints, greedily selecting the nearest available unit for each destination in descending priority order. Comparison reports covered count, priority-weighted coverage, route distance, estimated route minutes, and utilization. These are computed from each proposed assignment; no improvement is assumed. Exact enumeration suits the current five-unit demo inventory and will need a solver or bounded strategy if the city/resource problem grows substantially.

Priority score is a transparent 0–100 synthetic planning index: 0.25 × capped occupants/100 + 0.25 × current exposure indicator + 0.15 × capped current depth/1.5 m + 0.10 × ML future exposure indicator + 0.10 × nearest-road access deterioration (0 open, 0.5 caution, 1 flooded/closed/manually blocked) + 0.10 × resource scarcity (one minus compatible standby units divided by eligible affected buildings, floored at zero) + 0.05 × facility criticality (1 hospital, 0.5 shelter). The ML future-exposure label is distinct from observed current flood state. This score is neither calibrated nor a life-safety triage standard.
