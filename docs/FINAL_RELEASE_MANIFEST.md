## Generate a machine-readable manifest

Run `pwsh -NoProfile -File scripts/test-release-manifest.ps1` to exercise valid and invalid disposable repository copies. The 11 cases verify required dependencies and model artifacts, missing-file rejection, empty frontend-build rejection, model hash mismatch rejection, exact source commit, frontend asset hashes, valid generated JSON, and absence of secret-like values or personal machine paths. The fixtures are temporary clones; the real model files are never renamed, removed or corrupted.

After the final source commit and production build, run `scripts/write-release-manifest.ps1`. It fails closed if any mandatory input is absent or empty, verifies the model checksum against both the saved reliability report and model metadata, and cross-checks calibrator and support checksums against the reliability report. Newline-bearing JSON metadata is normalized to LF before its recorded hash is computed. The JSON output is ignored under `artifacts/part16-release-manifest.json`, outside the tracked source tree, so it does not create a self-referential Git SHA or become a stale committed manifest. Regenerate it from the exact final checkout and report that SHA and the exact-head hosted run in the PR delivery report; do not place the eventual commit SHA inside this file or documentation commit.

Review the generated output before sharing; it contains relative paths and hashes, not the user database, browser profile, environments, credentials or caches.

No zip is generated by default. If a source archive is needed after review, create it from the exact reviewed commit with `git archive`, then inspect its contents and hashes. Do not include local environments, `.env` files, databases, browser data, caches, or recordings. No Git tag, GitHub Release, hosted deployment, repository visibility change, or Innotech submission is performed by this process.
